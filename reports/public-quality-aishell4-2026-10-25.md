# AISHELL-4 公开会议录音质量基线（2026-10-25）

## 数据与口径

使用 [OpenSLR SLR111 的 AISHELL-4](https://www.openslr.org/111/) 真实 8 通道普通话会议录音，来源录音 `M_R003S02C01` 及其人工 TextGrid 标注从 [AISHELL-4 镜像](https://huggingface.co/datasets/AISHELL/AISHELL-4/tree/main/test) 取单文件。原始数据许可按 OpenSLR 页面所列 **CC BY-SA 4.0** 处理；镜像页面的许可元数据与上游不一致，因此没有把录音、标注或完整预测文字加入仓库。下载文件 SHA-256：FLAC `b74f2c00c374b899c7b0154a1b492a9429b0dd270e0f236d83abff0f7a2c7e0f`，TextGrid `bd4561fc778fdd28ef48e59257e791cbd33430c11b26493d7e24166833084879`。

机器为 MacBook Air M4、10 核、16 GiB，macOS 15.6 arm64；`sherpa-onnx 1.13.8`，仓库 `models/manifest.json` 固定的 online-small、offline-multi、3D-Speaker 与 Pyannote 分段模型。片段取原 FLAC 的**第 0 声道**，导出为单声道 16 kHz PCM16；用 `scripts/prepare_aishell4_eval.py --channel 0` 重新导出的 WAV 已与实际上传文件逐字节比对一致。文字从 TextGrid 读取，去 `<sil>`、`<#>`、空白和标点。中文 CER 为按时间顺序拼接后的字符编辑距离 / 参考字符数。片段之间不得把同一次会议的重复语音当作独立语料估计置信区间。

两个多人窗口在正式窗口**以外**取同一会议中对应人员的 10–20 秒语音注册声纹：001-M 取 30–42 秒，006-F 取 235–255 秒，005-F 取 705–715 秒；测试窗分别为 420–510 秒与 420–540 秒。因此这是同场景、短注册音频条件，不代表跨设备或跨日期声纹识别率。所有评测输入和逐任务结果存于本机 Git 忽略目录 `data/datasets/aishell4/`。

## 文件 ASR 与热词配对

以下三个**无参考重叠**的窗口使用相同 WAV、模型与参数各执行一次关闭热词和启用热词。热词集 v3 固定为“商场、客流量、家电、女装、销售策略、电子”，权重 1.0；其中部分词在某个窗口不存在，用来检查误插入。热词仅传给解码器，评测脚本不会把参考词写入预测结果。两次运行都成功，热词启用任务保存了集 ID 和版本 3。

| 来源时间 | 时长 | 参考字符 | 关热词 CER | 开热词 CER | 目标词命中（关 → 开） | 不在参考中的热词误插入（关 → 开） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 24–90 秒 | 66 秒 | 249 | 102/249 = 40.96% | 102/249 = 40.96% | 2/2 → 2/2 | 0/4 → 0/4 |
| 90–180 秒 | 90 秒 | 345 | 77/345 = 22.32% | 77/345 = 22.32% | 1/3 → 1/3 | 0/3 → 0/3 |
| 270–340 秒 | 70 秒 | 285 | 59/285 = 20.70% | 59/285 = 20.70% | 2/2 → 2/2 | 0/4 → 0/4 |
| 合计 | 226 秒 | 879 | **238/879 = 27.08%** | **238/879 = 27.08%** | **5/7 → 5/7** | **0/11 → 0/11** |

这组样本**未观察到热词收益**：CER 和目标词命中均无变化。较早一次只用“商场经理、客流量、电子”的探索性配置，在 24–90 秒窗口从 102 错字符变为 101；这是单字符波动，不能作为稳定收益。CER 也受文件分段漏检影响：24–90 秒窗口的输出首段从片段内约 14 秒才开始，参考的前一段发言没有进入输出；故此值是平台端到端文件转写误差，不等同纯 ASR 模型的声学识别误差。

同一 24–90 秒 WAV 还按真实速度以 100 ms 帧分别进行了**单路流式**热词关/开测试；两次均完整发送 660 帧、任务完成且无客户端或服务端错误、服务端丢帧 0。用压测器收集的最终文字按上述参考与归一化方法重算，关/开均为 **43/249 = 17.27% CER**，目标词均 **2/2**，缺席目标词误插入均 **0/4**，热词仍无可测收益。首个 partial 分别约 **2.36/2.34 秒**，超过本项目预设的 2 秒单路首字门槛，因此两次压测器的总门槛都为 `fail`；这不改变其任务完成与 CER 结果。流式最终文字来自在线识别与实时离线复识流程，文件模式还经过离线分段，两者流程不同，17.27% 与 40.96% 的差异不能归因于单个模型。

## 多人分段与注册命中

这里使用 `evaluation.quality` 的 **DER-like**：先按最大时间重叠映射本地说话人 ID，再计算参考非重叠语音中错标或漏标的时长占比；**不是标准 DER**。人工参考出现双人同时讲话的区间被排除，边界误差因此标为不可评估。注册命中率按参考非重叠说话时长计，要求预测 `registered_speaker_id` 与预先注册 ID 相同。自动人数配置为 `ASR_DIARIZATION_NUM_SPEAKERS=-1`；另用真实人数作为已知输入复测，仅说明给出人数后的潜在差异，不能作为默认自动能力。

| 窗口 | 参考人数 | 自动估计输出本地标签 | DER-like 自动 → 已知人数 | 注册命中自动 → 已知人数 | 排除重叠时长 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 420–510 秒 | 2 | 3 | 29.29% → 26.73%（配置 2） | 64.58% → 64.58% | 3.65 秒 |
| 420–540 秒 | 3 | 7 | 30.04% → 24.78%（配置 3；实际输出 2 个标签） | 52.23% → 54.15% | 15.14 秒 |

自动人数把人声拆成过多本地标签；明确人数后 DER-like 降低，但三人窗仍只给出两个本地标签。三个声纹均已提前注册，而注册命中只有约 52–65%，说明当前阈值与分段策略尚不能用于可靠的会议身份自动判定。前者是分段与说话人归并误差，后者是注册身份匹配误差，两种指标不能互换。多人窗口存在语音重叠，按开始时间拼接参考文字的全局 CER 没有唯一词序，评测脚本把该 CER 标为**不可评估**。

人数配置是在独立评测服务启动时通过 `ASR_DIARIZATION_NUM_SPEAKERS=-1`、`2`、`3` 分别设置，并依次提交相同窗口的文件任务；任务结果 JSON 本身不记录该服务端环境变量，因此这些已知人数结果仅按本轮服务启动参数记录为调参试验，不能仅从任务 JSON 独立还原配置。初次 `evaluation.quality` 版本对重叠多人参考仍写入了拼接 CER 数字；这些旧版 CER 数值**不采用**，本地指标文件已用新版工具重算。现版 `evaluation.quality` 和 `compare_public_outputs.py` 均将重叠参考的全局 CER 标为不可评估。

## 可复现方法与限制

重建片段与参考标注的命令见 [评测工具说明](../evaluation/README.md)。无重叠窗口的成对结果由 `scripts/compare_public_outputs.py` 从 API 原始任务 JSON 计算；多人窗口的 DER-like 和注册命中由 `python -m evaluation.quality` 计算。脚本修正和真实样本结果已由独立验证者复核：第 0 声道 WAV 字节一致，重叠区间被正确排除，热词 on/off 由任务中的 `hotword_set_id` 校验。

这是一场会议的短片段探索性基线，样本量、场景和说话人都很有限。高重叠、多说话人窗口和部分首段漏检是当前明显问题；商业场景的准确率仍需目标业务录音及独立人工标注。热词编辑也受离线模型词表约束：例如本次尝试的“促销”在线可编译，但离线词表缺少“促”，文件任务无法使用该热词集；必须在正式创建文件任务前检查两种模型的编译兼容性。
