# 最终进程结构的 Mac 压测（2026-10-25）

## 条件与限制

- 机器：MacBook Air，Apple M4、10 核、16 GiB RAM，macOS 15.6 arm64，无 NVIDIA GPU。压测客户端与服务端同机，可能与服务端争用 CPU；资源采样只汇总 API 进程及其实时离线复识子进程、外置文件 Worker，不把客户端计算入服务端资源。
- 模型：`models/manifest.json` 固定的 online-small、offline-multi、3D-Speaker 声纹及 Pyannote 分段模型。在线和离线识别默认各 2 线程，单个外置文件 Worker，实时离线复识为一个独立子进程，实时 final 队列上限 16。服务 `ASR_MAX_STREAMS=16`，文件分段指定两位说话人；两个注册样本来自与待转写片段不同的 AISHELL-3 原始音频。
- 输入：仓库内获准分发的 [AISHELL-3 A/B/A/B 样例](../demo_assets/aishell3/README.md)，转换为 16 kHz 单声道 PCM16 WAV，每段约 7.049 秒；选择两词热词集 v2。短音频的重复上传/回放只用于可复现容量基线，不代表真实会议、噪声或重叠发言。
- 本报告仅在该机器、模型、样例、热词与门槛下成立。PSS 在 macOS 本轮不可用；RSS 由进程树逐秒采样，首个 CPU 样本用于建立基线而为空值。原始 JSON/CSV 留在未入库的 `data/baseline/integration-20261025/`，图表不含转写文本、人员 ID 或本机地址。

## 文件任务：2 个持续提交位，10 分钟

`--mode file --concurrency 2 --tier-duration-seconds 600 --max-file-jobs-per-tier 2000`，同时指定 API 与文件 Worker 两个资源根，后代进程按 PID 去重。实际墙钟 **601.0 秒**，未触发 2000 个任务上限；**1152/1152 成功，0 错误**。处理音频合计 **2.256 小时**，按墙钟折算 **13.51 音频小时/小时**。队列等待 P95 **0.641 秒**，单任务 RTF P95 **0.149**。

API 配置根及其后代、Worker 进程树合计 CPU 平均 **67.4%**、峰值 **76.7%**（100% 约为一个逻辑核）；RSS 平均约 **300.5 MiB**、峰值约 **331.9 MiB**。单独观察到的 Worker RSS 峰值约 **222.9 MiB**，API 角色进程树峰值约 **109.2 MiB**。前 2 分钟与末 2 分钟总 RSS 中位数约 **306.0/271.4 MiB**，本轮未观察到持续上涨，但 10 分钟和 macOS 内存压缩不足以证明长期平台期。

通用 `gates` 整体为 `not_evaluable`：文件任务的错误率门槛通过，实时首字、stop→completed、积压和丢帧在文件模式中没有定义，不能将缺失值写成零或声称五项门槛全通过。[查看脱敏离线图表](mac-file-2x10min-2026-10-25.html)。2 个提交位仅是本轮负载，并非测得的文件最大并发数。

## 混合任务：4 路实时 + 1 个持续文件提交位，10 分钟

使用相同模型、声纹库、热词 v2 与公开音频，实时每帧 100 ms，文件任务持续提交。实际墙钟 **600.2 秒**；**4/4 路实时完成，580/580 个文件任务成功，0 错误**。文件音频合计 **1.136 小时**，按墙钟折算 **6.81 音频小时/小时**，文件队列等待 P95 **0.480 秒**，文件 RTF P95 **0.149**。

实时首个 partial P95 **0.511 秒**，stop→completed P95 **0.171 秒**。四路共 **1160** 个最终片段，全部有说话人标签；观察到 **1156** 次相邻标签切换，标签相对片段音频结束的到达延迟 P95 **1.823 秒**。客户端迟发帧 **0**、最大积压 **0.018 秒**，4/4 路均报告服务端丢帧 **0**。预设的错误率、首字、stop 后完成、积压和丢帧五项初始门槛均为 `pass`；说话人标签数量与切换次数是事件完整性指标，不证明身份准确率。

API 配置根及其后代、Worker 进程树合计 CPU 平均 **155.9%**、峰值 **352.8%**；总 RSS 平均 **648.9 MiB**、峰值 **723.3 MiB**。API 角色进程树 RSS 峰值 **518.1 MiB**，文件 Worker 峰值 **208.1 MiB**。前 2 分钟与末 2 分钟总 RSS 中位数约 **643.2/641.7 MiB**，未见 10 分钟内单调上升。[查看脱敏离线图表](mac-mixed-4live-1file-10min-2026-10-25.html)。这证明该负载配置在本次公开短音频下通过初始门槛，尚未测得实时最大并发。

## 纯实时：8 路，10 分钟

同一套服务、模型、热词 v2 与公开音频，100 ms PCM 帧按真实时间发送，8 路各播放 600 秒；**8/8 会话完成，0 错误**。首个 partial P95 **0.493 秒**，stop→completed P95 **0.393 秒**；客户端迟发帧 **0**、最大积压 **0.0032 秒**，8/8 路报告服务端丢帧 **0**。五项初始门槛均为 `pass`。

共收到 **2320** 个最终片段且全部有说话人标签，**2312** 次相邻标签切换，标签相对片段音频结束的到达延迟 P95 **2.097 秒**。这些数字验证事件完整性，不验证声纹身份准确率。

API 及其实时复识子进程、外置文件 Worker 的进程树合计 CPU 平均 **237.5%**、峰值 **583.6%**；RSS 平均 **574.8 MiB**、峰值 **643.1 MiB**。API 角色进程树 RSS 峰值 **627.2 MiB**，空闲文件 Worker 峰值 **16.4 MiB**。前 2 分钟与末 2 分钟 RSS 中位数约 **566.0/559.9 MiB**，本轮未观察到持续上涨。[查看脱敏离线图表](mac-live-8x10min-2026-10-25.html)。8 路是已通过的短时档位，仍需更高档位与长稳验证才能确定本机稳定容量。

## 纯实时：12 路，10 分钟，失败档

同样条件下每路播放 600 秒，只有 **9/12** 路完成，**3** 路报错：`offline_final_queue_full` 2 次、在线 `queue_full` 1 次；错误率 **25%**，超过初始 **1%** 门槛。最大客户端积压 **0.839 秒**、迟发帧 **75**，积压也超过 **0.5 秒**门槛。首个 partial P95 **0.470 秒**及 stop→completed P95 **1.227 秒**只来自可观测会话，不能抵消失败。仅 **9/12** 路有服务端丢帧遥测，其余为不可评估，不能声称 12 路零丢帧。总门槛为 `fail`。

成功会话共 **2610** 个最终片段且均有标签，观察到 **2601** 次相邻标签切换；失败的三路没有完整结果，不应计入成功的说话人质量。CPU 平均 **363.8%**、峰值 **786.2%**；RSS 平均 **633.4 MiB**、峰值 **699.1 MiB**。前 2 分钟与末 2 分钟 RSS 中位数约 **652.4/611.1 MiB**，本轮瓶颈表现为队列/时序而非持续内存增长。[查看脱敏离线图表](mac-live-12x10min-2026-10-25.html)。在本机和这套参数下，12 路不是稳定通过档位。

## 纯实时：10 路，计划 10 分钟，提前失败

同样条件下计划每路播放 600 秒，但 **10/10 路均在约 7.4 分钟内因在线 `queue_full` 失败**，WebSocket 关闭码均为 1013，故实际没有完成 10 分钟。首个 partial P95 **0.482 秒**只表示初期可回应；没有成功会话，stop→completed 与最终说话人片段均不可评估。客户端最大积压 **0.608 秒**，迟发帧 **147**；无完整会话的服务端丢帧遥测，不能补零。总门槛为 `fail`。

采样期间进程树 CPU 平均 **374.2%**、峰值 **733.5%**，RSS 平均 **605.9 MiB**、峰值 **698.2 MiB**。前 2 分钟与末 2 分钟 RSS 中位数约 **594.7/587.1 MiB**。[查看脱敏离线图表](mac-live-10x10min-2026-10-25.html)。这是提前失败的档位，不应把计划音频时长当成已完成处理量。

## 纯实时：9 路，10 分钟

同样条件下 **9/9** 路各播放并完成 600 秒，**0 错误**。首个 partial P95 **0.507 秒**，stop→completed P95 **0.315 秒**；客户端最大积压 **0.377 秒**，迟发帧 **27**，9/9 路报告服务端丢帧 **0**。五项初始门槛均为 `pass`，但迟发帧与积压表明比 8 路更接近边界。

共 **2610** 个最终片段且全部有说话人标签，**2601** 次相邻标签切换，标签延迟 P95 **2.139 秒**；这些是事件完整性指标。进程树 CPU 平均 **265.2%**、峰值 **621.6%**；RSS 平均 **610.4 MiB**、峰值 **683.8 MiB**。前 2 分钟与末 2 分钟 RSS 中位数约 **596.9/603.7 MiB**，10 分钟内存在小幅波动，不能据此判定长期内存平台期。[查看脱敏离线图表](mac-live-9x10min-2026-10-25.html)。本次短时档位 9 路通过、10 路提前失败；9 路还需 30 分钟长稳结果才能作为本机的长期通过档位。

## 纯实时：9 路，30 分钟长稳

同样条件下 **9/9** 路各发送并完成 **1800 秒**，合计 **4.5 音频小时**，**0 错误**。首个 partial P95 **0.488 秒**、stop→completed P95 **0.426 秒**；客户端最大积压 **0.143 秒**、迟发帧 **9**，9/9 路报告服务端丢帧 **0**。五项初始门槛均为 `pass`。总计 **8037** 个最终片段且全部有说话人标签，**8028** 次相邻标签切换；其中 **8036** 个片段有可计算的标签延迟，P95 **2.252 秒**。其余一个片段不满足延迟计算条件，未以零补足。

进程树 CPU 平均 **311.8%**、峰值 **706.9%**；RSS 平均 **598.0 MiB**、峰值 **690.3 MiB**。API 角色进程树 RSS 峰值 **682.6 MiB**，空闲文件 Worker 峰值 **7.7 MiB**。前 2 分钟与末 2 分钟 RSS 中位数约 **612.1/582.1 MiB**，30 分钟内未观察到持续内存上涨。CPU 的每 5 分钟中位数从约 **255%** 逐段升至 **373%**；这是需要进一步定位的资源增长迹象，不能只凭五项实时门槛通过就宣称无限时稳定。[查看脱敏离线图表](mac-live-9x30min-2026-10-25.html)。目前可确认这台 Mac 在公开循环样本与本配置下 **9 路连续 30 分钟满足五项实时门槛**；CPU 漂移和更长时长仍需调查，生产容量需在目标机器与业务录音上复测。
