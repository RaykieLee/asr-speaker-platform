# 最终进程结构的 Mac 压测（2026-10-25）

## 条件与限制

- 机器：MacBook Air，Apple M4、10 核、16 GiB RAM，macOS 15.6 arm64，无 NVIDIA GPU。压测客户端与服务端同机，可能与服务端争用 CPU；资源采样只汇总 API 进程及其实时离线复识子进程、外置文件 Worker，不把客户端计算入服务端资源。
- 模型：`models/manifest.json` 固定的 online-small、offline-multi、3D-Speaker 声纹及 Pyannote 分段模型。在线和离线识别默认各 2 线程，单个外置文件 Worker，实时离线复识为一个独立子进程，实时 final 队列上限 16。服务 `ASR_MAX_STREAMS=16`，文件分段指定两位说话人；两个注册样本来自与待转写片段不同的 AISHELL-3 原始音频。
- 输入：仓库内获准分发的 [AISHELL-3 A/B/A/B 样例](../demo_assets/aishell3/README.md)，转换为 16 kHz 单声道 PCM16 WAV，每段约 7.049 秒；选择两词热词集 v2。短音频的重复上传/回放只用于可复现容量基线，不代表真实会议、噪声或重叠发言。
- 本报告仅在该机器、模型、样例、热词与门槛下成立。PSS 在 macOS 本轮不可用；RSS 由进程树逐秒采样，首个 CPU 样本用于建立基线而为空值。原始 JSON/CSV 留在未入库的 `data/baseline/integration-20261025/`，图表不含转写文本、人员 ID 或本机地址。

## 文件任务：2 个持续提交位，10 分钟

`--mode file --concurrency 2 --tier-duration-seconds 600 --max-file-jobs-per-tier 2000`，同时指定 API 与文件 Worker 两个资源根，后代进程按 PID 去重。实际墙钟 **601.0 秒**，未触发 2000 个任务上限；**1152/1152 成功，0 错误**。处理音频合计 **2.256 小时**，按墙钟折算 **13.51 音频小时/小时**。队列等待 P95 **0.641 秒**，单任务 RTF P95 **0.149**。

API 配置根及其后代、Worker 进程树合计 CPU 平均 **67.4%**、峰值 **76.7%**（100% 约为一个逻辑核）；RSS 平均约 **300.5 MiB**、峰值约 **331.9 MiB**。单独观察到的 Worker RSS 峰值约 **222.9 MiB**，API 角色进程树峰值约 **109.2 MiB**。前 2 分钟与末 2 分钟总 RSS 中位数约 **306.0/271.4 MiB**，本轮未观察到持续上涨，但 10 分钟和 macOS 内存压缩不足以证明长期平台期。

通用 `gates` 整体为 `not_evaluable`：文件任务的错误率门槛通过，实时首字、stop→completed、积压和丢帧在文件模式中没有定义，不能将缺失值写成零或声称五项门槛全通过。[查看脱敏离线图表](mac-file-2x10min-2026-10-25.html)。2 个提交位仅是本轮负载，并非测得的文件最大并发数。
